the plugin

Retell the PR in Lean.
That is what we check in.

Lean cannot read your program. So we do not ask it to. A plugin writes a short Lean retelling of what the change is allowed to do. If a person cannot read that retelling and agree, stop. That agreement is the point. Humans and agents argue about the retelling, not the raw diff.

What the plugin does on a PR

1 · retell

Here is this change, said in Lean, in a page a person can review. What it may do. What it must never do.

2a · still matches

The proof attempt says the old rules still hold. The retelling did not change the contract. You can merge the understanding as-is.

2b · the rules changed

The proof attempt says this PR updates the contract. That is fine only if you meant to. The spec change is the thing you review.

Why trust the retelling

Because that is the only place Lean and the team share a language. We will not get a magic bridge from Python to Lean. We get a retelling clear enough that a human says “yes, that is what I meant,” and an agent is stuck with that meaning when it writes the rest.

If the retelling is mush, none of this works. The plugin’s job is to make that obvious.
